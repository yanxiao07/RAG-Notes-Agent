# 企业级 RAG 对照审查与下一阶段计划

## 1. 审查范围

本审查参考文章《工业级的 RAG 优化选型 · 识海》：

<https://sealearn.yuque.com/org-wiki-sealearn-syaeae/oi5uvb/sy2eibydtutm1g13>

文章把企业 RAG 拆成知识工程、Query 改写、检索召回、Rerank/截断、可信生成、过程评测、
Agentic RAG 和线上反馈八层。本项目按当前代码、迁移、测试、Docker 验收和已有评测记录进行
对照，结论只描述本项目已验证的能力，不引用文章中的指标作为本项目结果。

## 3. 下一阶段优先级

### P0：先保证回答不会因为上下文和来源处理而失真

1. **Evidence Budget Builder（已落地基础版）**：统一按模型 Token 预算组装证据，保留高相关片段、
   标题、条件限制、操作步骤、代码围栏和 URL；当前使用确定性头尾截断和保守估算，后续接入模型 tokenizer
   与语义压缩前仍需用真实评测集验证。
2. **URL/Source Validator（已落地基础版）**：只展示证据中保存的来源 URL，Worker 异步检查 2xx/重定向、
   重定向目标和内容类型；失效链接在引用中标记为不可用。默认关闭的独立 Worker 可按低频周期/批次复核；
   后续补充来源可信度排序、URL 可用率评测和正文变更检测。
3. **阶段事件与 Badcase 归因（已落地基础版）**：已将 `route/rewrite/retrieve/fuse/rerank/truncate/answer/judge`
   固化为脱敏 JSON 事件，并对确定性风险生成待复核项。`route/rewrite` 可进行仅分析回放和候选差异对比；
   下一步接入人工分诊回流，并在检索器状态拆分后扩展更细粒度回放，不保存正文或密钥。
4. **入库敏感信息边界（已落地基础版）**：对具有明确厂商格式的访问 Token 使用固定占位符脱敏，避免其进入
   原文、向量、缓存和生成上下文；不做宽泛正则猜测，以降低误伤技术文档的风险。历史文档通过显式重切分
   将脱敏内容替换进切块与向量，完成后需重建同版本评测基线。

### P1：提升召回覆盖，并让 Agent 具备可控的多步检索

1. **双路召回**：定向路使用实体/业务 Tag/来源过滤，通用路保持宽召回；两路分别限额，去重后以 RRF
   融合，任何定向过滤失败都保留通用兜底。
2. **Dynamic Top-K（已落地基础版）**：根据问题类型、候选分数间隔、文档覆盖和 Evidence Budget 动态调整 K，设置
   最小/最大上限与固定 K 回退；后续需要在真实评测集验证 Recall、噪声率和延迟收益。
3. **业务标签治理（已落地基础版）**：文档/笔记标签采用受控词表、来源和更新时间版本；自动抽取只能
   产生待审核建议。下一步用版本化数据集评测标签路径，再决定是否保持可选召回增强或引入受控权重。
4. **Bounded Agentic RAG（已落地基础版）**：关系/多跳问题可启用最多 N 步的确定性 Planner；每步只能调用
   只读检索工具，证据充分性检查依据覆盖、locator 增量、Token 与延迟决定结束或再检索。下一步应在版本化
   评测集比较单步与有界多步的覆盖、噪声、延迟与 Token 成本，再评估是否引入受约束 LLM Planner。
5. **Feedback Loop（已落地基础版）**：已有回答 helpful/unhelpful、原因枚举、人工分诊、受审批的
   知识/评测草稿和仅导出 `approved` 用例的原子 CLI。下一步应建立 Git 评审约束和真实评测集扩充，而不是让系统自动学习或自动宣称收益。

### P2：知识质量与规模化优化

1. 在真实评测集证明结构切分不足后，再引入 embedding breakpoint/语义切分，并保留确定性回退。
2. 引入文档有效期、来源可信度、冲突检测和 supersedes 关系；过期/冲突知识默认降权而非静默删除。
3. 对高频、高风险、高价值实体选择性建图，评估 Leiden/Louvain 和社区向量索引的成本收益。
4. 提供可选 DeepEval 适配器作为外部评估员，但确定性指标和本项目引用/拒答门禁仍是主门禁。

### 暂不纳入当前交付

- Query Rewrite/生成模型的 LoRA 或 RL 训练。
- Evidence Faithfulness 的强化学习训练。
- 全量 GraphRAG、全量社区向量化和无限步 Agent。

这些方向都可能有价值，但需要真实线上轨迹、标注数据、成本预算和离线训练基础；在 P0/P1 的可审计
能力完成前提前引入，会增加复杂度而无法证明业务收益。

## 4. 阶段验收指标

每项优化都必须在同一版本化评测集上和当前基线对照，至少报告：

- 检索：Top1、Recall@K、MRR、必需关键词覆盖率、噪声率、跨文档覆盖率。
- 生成：引用覆盖率、拒答正确率、URL 可用率、Evidence Faithfulness 抽样结果。
- Agent：成功完成率、平均/最大检索步数、重复检索率、Token 消耗、P50/P95 延迟。
- 工程：缓存命中率、模型失败率、重试次数、吞吐和数据库/Redis 资源占用。

任何来自文章、其他项目或演示样例的 Top1/MRR/延迟百分比都不能直接写成本项目成果；只有在本项目
固定评测集、固定模型和可复现脚本中得到的差值才可以进入结果文档和简历。
