# 交付路线图

## Phase 0: 设计与契约

- [x] 产品需求、架构、API、数据、异常/日志规范。
- [x] 构建可演进的目录与质量门禁定义。

## Phase 1: 领域骨架

- [x] 通用 `Idempotency-Key` 持久化与 24 小时请求体去重，覆盖文档、笔记和 Agent 写操作；相同请求重放原响应，不同请求体返回 `IDEMPOTENCY_CONFLICT`，失败请求释放预留。
- [x] FastAPI 应用、配置、请求 ID、统一异常和结构化日志。
- [x] 知识库与笔记 API，仓储抽象、乐观锁和测试。
- [x] Alembic 首个生产迁移、默认工作区隔离和可配置 API Key 认证。

## Phase 2: RAG 基础闭环

- [x] 文件上传、文档入库任务状态机与可由后台 Worker 调用的执行函数。
- [x] TXT/Markdown、PDF、DOCX 解析、段落切块和扩展注册表。
- [x] 网页/URL 文档导入、正文抽取、SSRF 防护和原始 URL 可追溯引用。
- [x] Typora Markdown 专用解析与代码围栏感知切块，支持历史文档重建恢复代码结构。
- [x] 已导入文档归档删除、索引清理和同内容重新导入。
- [x] 本地确定性检索、引用模型和检索调试 API。
- [x] 查询路由、本地 Embedding 索引和 RRF 混合召回骨架；运行配置状态与索引重建入口。
- [x] 嵌入配置修订号、知识库索引失效门控与重建激活，避免模型切换后混用旧向量。
- [x] Redis 优先、内存 LRU 回退的查询向量缓存；候选噪声预过滤、重排缓存和 Cross-encoder 可替换适配器。
- [x] 多路由 Query Router：区分 direct、memory、clarify、rag，避免无关问题消耗检索资源。
- [x] 级联 Hybrid Query Router：高置信度规则优先，LLM 仅处理灰区；结构化输出、置信度阈值、显式 RAG 强制和安全回退。
- [x] 结构化多路 Query Rewrite Plan：保留原始问题，补充主查询、子查询和同义词，按 locator 去重并加权 RRF。
- [x] Parent-Child Retrieval：子块精确召回、同章节相邻上下文扩展、长度上限、去重和子块引用锚点。
- [x] RAG 链路诊断契约：查询改写、关键词/向量候选、RRF、重排、缓存和阶段耗时可审计并在研究页展示。
- [x] 可配置 Metadata Boost：标题、章节和来源类型只做轻量排序加权，统计加权候选并纳入评测。
- [x] 手工笔记精选知识层：版本化编辑、独立向量快照、关键词与语义混合召回、重建回填。
- [x] PostgreSQL pgvector + FTS 适配器、双写向量列、固定维度 HNSW/GIN 迁移和 RRF 契约。
- [x] PostgreSQL workspace RLS 迁移、Session 级租户上下文、向量回填脚本和离线评测质量门禁。
- [~] 真实 PostgreSQL 环境回填执行、租户 RLS 演练、生产压测与评测集基线：Docker 环境的回填、RLS 演练、合成业务语料基线和隔离检索压测已完成；真实业务数据的人工标注集、容量基线与正式质量门禁仍未完成。
  已在 2026-08-06 Docker 验收栈完成 PostgreSQL/pgvector、非 superuser、强制 RLS、跨工作区隔离、
  Redis 缓存和检索基准演练；尚未完成真实业务评测集扩充与生产压测，不能将合成样本结果外推为线上质量。

## Phase 2.5: 企业级 RAG 质量闭环

设计审查结论与文章对照矩阵见 `docs/13-rag-enterprise-gap-analysis.md`。本阶段先解决可验证性和
上下文安全，再扩展召回与 Agent 路径；所有收益必须使用本项目版本化评测集测量。

- [x] Evidence Budget Builder 基础版：Token 预算、代码围栏保护、原始引用不变和截断原因诊断；
  厂商 tokenizer、语义压缩和更细粒度条件保留仍需真实评测后迭代。
- [x] Source/URL Validator：网页导入后异步校验 HTTPS/SSRF 边界内的状态码、逐跳重定向与 HTML 内容类型；来源健康状态与 approved domain 命中写入文档和引用快照，失效链接在 UI 标记为不可用但不删除已入库证据。
- [x] Dynamic Top-K：按问题模式、分数间隔、跨来源覆盖和 Token 预算自适应 K；关闭时严格回退请求固定 K，研究页/API 输出停止原因和选择诊断。
- [x] 定向实体召回 + 通用召回双路候选，按 locator 去重后 RRF 融合并保留通用兜底；受控业务标签治理单列为下一项。
- [x] 受控业务标签治理：知识库级受控词表、文档/笔记自动规则建议、人工审批、审计记录和 React 审核界面。
  已批准标签可选地作为定向候选路径与 Hybrid 进行 RRF 融合，默认关闭；排序收益仍待版本化评测集验证，
  不得据此宣称质量提升。
- [x] RAG 分阶段事件契约基础版：问答运行固化 `route/rewrite/retrieve/fuse/rerank/truncate/answer/judge`
  的脱敏快照，保存哈希、候选 locator、计数、耗时、错误码和策略版本；提供按运行查询 API，并对
  `retrieval_miss`、上下文截断、重排降级和生成失败进行确定性归因。
- [x] 从指定阶段复跑后续链路基础版：`route/rewrite` 边界可创建仅分析的回放运行，复用受保护的
  会话用户消息引用，不生成新回答、不改写历史引用；输出策略版本、输入哈希和新增/移除候选 locator。
  当前检索器将 Rewrite、Hybrid、RRF、Rerank 封装为一个原子调用，`retrieve/fuse/rerank` 的细粒度热启动
  需要后续拆分检索器状态后再支持。
- [x] 回答 helpful/unhelpful 反馈与分诊队列基础版：反馈关联 Agent Run 与阶段事件 ID；无帮助反馈按固定原因
  自动进入待分诊队列，审核角色可标记状态及后续目标，问答页只提供结构化反馈控件而不记录自由文本。
- [x] 知识草稿和回归评测用例回流：仅允许 `resolved` 且目标匹配的分诊项创建一对一草稿/用例，
  approver/owner 批准知识草稿后同事务写入笔记知识层和索引；评测用例批准后进入数据库受控集合，
  后续必须显式导出并经代码审阅纳入版本化评测集。所有动作支持幂等键、工作区 RLS 和脱敏审计；
  禁止自动把点踩内容直接入库。
- [x] 已批准反馈评测用例受控导出：CLI 仅按工作区和知识库读取 `approved` 用例，稳定输出兼容离线评测的
  JSON 数组；默认拒绝覆盖、原子写入、无用例失败并输出内容哈希。导出文件仍需 Git 审阅后才能作为评测基线。
- [x] 可复现实验清单与严格比较：离线评测报告绑定评测集 SHA-256、知识库、Embedding/索引/图谱修订号、
  模型身份和策略摘要；比较命令默认拒绝不兼容报告，显式豁免只能用于人工探索且永不通过质量门禁。
- [x] 查询路由独立评测：版本化用例覆盖 `direct/memory/clarify/rag` 与实时能力边界，CLI 在不检索、
  不生成、不写入会话的条件下输出脱敏准确率和分路由召回；真实业务路由集仍需经人工脱敏标注后接入。
- [x] 检索策略实验快照：`baseline/rewrite/rerank/current` 只派生内存 Settings，不改写用户配置；报告记录
  请求开关、实际 Provider、缓存和模型失败回退，为后续真实业务 A/B 建立可复现边界。
- [x] 无答案检索门禁：评测契约显式区分 `grounded/no_answer`，局部问题候选缺少实体/短语支持时清空证据，
  复用生成层拒答与无引用契约；关系/全局图谱问题豁免，词表与真实业务拒答率仍需持续校准。
- [x] 导入内容高置信凭证脱敏：上传、网页抓取、任务重试与重切分在文本指纹、持久化、切块、Embedding 前
  统一替换 API Token；历史资产须通过显式重切分完成受控修复，避免系统在未知成本下自动调用外部模型。
- [x] 文档时效/来源/替代治理基础版：人工维护可信度、生效/到期、冲突和 `supersedes` 关系；统一检索门禁
  排除未来生效与已替代资料，对过期/冲突资料降权并输出计数诊断。自动冲突识别、来源优先级学习仍需真实业务口径与人工标注。
- [x] 网页来源低频批量复核：独立 Worker 以周期和批次领取到期网页资料，复用 SSRF 边界；默认关闭，来源失败
  只更新健康状态且保留已存档证据。按业务优先级调度和来源可信度学习仍未实现。
- [x] 网页正文变更检测基础版：可选复核 Worker 对来源有效的网页比较脱敏文本指纹，仅标记变化和写入审计事件；
  不保存新正文、不替换原文/向量，必须由用户确认后手动重新导入。差异摘要、自动更新与来源优先级学习仍未实现。
- [x] 回答引用资料治理快照：SSE 与历史消息引用固化当次来源可用性、可信度、时效与冲突状态；界面仅在风险存在时标记，
  不以资料后续调整静默篡改历史回答。

## Phase 3: Agent 与知识图谱

- [x] 最小只读 LangGraph Runtime、工具调用策略、线程状态和运行快照持久化。
- [x] Checkpoint 恢复、工具注册表/输入校验、Runtime SSE 轨迹与多工作区隔离。
- [x] 写入提议审批中断节点（`create_note_proposal`）并同步工具状态与快照。
- [x] 多工具只读 Agent 工作流（`knowledge_search`、`knowledge_catalog`）与统一输入契约。
- [x] 统一 ChangeProposal action registry 与审批执行器；Runtime 写工具统一暂停并支持 approve/reject 幂等流转。
- [x] 扩展 `update_note`、`archive_document` 写动作，并在审批时校验版本、工作区和知识库边界。
- [x] 为 Proposal 增加风险等级、证据快照、过期时间和细粒度角色权限策略；生产角色由 `APP_WORKSPACE_ACTOR_ROLES` 映射决定。
- [x] 变更提议、审批执行和审计事件。
- [x] SSE 流、模型 Provider、对话状态持久化与证据引用问答。
- [x] GraphRAG-lite 实体/关系索引：入库时建立实体、关系和切块关联，关系问题一跳扩展并与 Hybrid RRF 合并。
- [x] 全局问题覆盖采样：按文档和高频实体选择代表证据，所有结果仍回指原始切块。
- [x] 实体/关系图谱的可选 LLM 抽取、版本化社区摘要与两层社区检索，支持局部/全局问答；模型失败自动回退规则抽取和确定性摘要。
- [ ] 生产级社区算法（Leiden/Louvain）、社区向量索引和离线质量门禁；需在真实 PostgreSQL/模型环境基准验证后启用。
- [x] Bounded Agentic RAG：关系/全局问题按确定性结构化 Planner 进入最多 N 步只读再检索；
  每步依据 locator 增量、来源覆盖、估算 Token 和总耗时进行充分性判断。步数/Token/延迟预算由服务端
  强制，预算耗尽时停止且输出稳定原因；普通本地问题及写工具保留单步和审批路径。

## Phase 5: 生产化

- [x] Docker Compose 开发/验收栈：PostgreSQL/pgvector、Redis、迁移、FastAPI、轮询 Worker 和 React。
- [x] 模型调用并发闸门、超时边界、指数退避重试和输出 Token 上限；Query Rewrite、Embedding、Rerank、Graph 抽取和问答流共用治理策略。
- [ ] CI、备份、限流和完整用户中心鉴权。
  已添加基础 CI 质量工作流（后端测试/Ruff/Pyright、前端格式与构建、评测脚本语法检查）；备份、限流和用户中心鉴权仍需独立生产阶段实现。
- [x] 入库任务租约、指数退避、死信状态和 Worker 崩溃回收。
- [x] API 分级限流：按认证工作区或匿名 IP 的哈希身份执行固定窗口配额，区分普通读取、写入、
  高成本生成和 Agent 研究请求；Redis 原子计数不可用时回退进程内桶，429 提供 `Retry-After` 与请求 ID。
- [x] 受保护 Prometheus 指标基础：可选 `/metrics` 仅输出 HTTP 请求量、路由模板延迟直方图与限流拒绝数；
  默认关闭，可由独立 Token 保护，严格禁止工作区、用户、IP、问题、文档与密钥进入标签。
- [x] PostgreSQL 归档备份与非破坏性恢复演练：维护容器使用 custom-format `pg_dump`、归档 TOC 校验与
  SHA-256；默认拒绝覆盖，恢复仅允许新建受限名称的演练库并要求同名显式确认，不允许覆盖源库。
- [~] OpenTelemetry Trace、告警规则、评测回归与完整安全审查：已提供默认关闭且脱敏的 OTLP HTTP/检索/模型调用 Trace、Collector profile、Prometheus 告警规则和评测工件原子写入；生产 Trace 后端接入、真实业务回归基线与完整第三方安全审查仍未完成。
- [ ] 可选 DeepEval 评估适配器；确定性引用、拒答和安全门禁仍作为主门禁。
