# 产品需求规格

## 1. 产品定位

RAG Notes Agent 是一个面向个人研究者和知识型团队的知识工作台。用户可将笔记、
Markdown、PDF、网页等内容纳入知识库，在保留可追溯原文证据的前提下完成问答、
知识整理、研究规划和笔记更新。

产品不以“更像聊天机器人”为目标，而以“让结论可追溯、变更可审计、知识可维护”为目标。

## 2. 用户与核心场景

| 用户 | 核心任务 | 成功标准 |
| --- | --- | --- |
| 研究者 | 汇总资料并得到可引用的结论 | 每个事实性结论可定位到原文 |
| 内容创作者 | 从私有笔记提取论据和写作素材 | 能复用已有知识且不混淆来源 |
| 小团队成员 | 管理项目知识、讨论与待办 | 变更来源清晰，成员可复核 |

## 3. MVP 范围

### 3.1 必须具备

1. 知识库、笔记、文档的创建、查看、更新、归档。
2. 文档异步入库：解析、清洗、切块、嵌入、索引、失败重试。
3. 混合检索：向量、全文、元数据过滤、融合排序和可选重排。
4. 基于引用证据的流式问答；无充分证据时明确拒答或标识不确定性。
5. 受控 Agent：查询知识、提出笔记/任务变更，用户确认后才持久化。
6. 运行审计：检索片段、模型、Prompt 版本、工具调用、审批和错误均可追踪。
7. RAG 质量闭环：记录分阶段检索诊断，支持回答反馈、badcase 分诊和审核后的知识/评测用例回流。

### 3.2 非目标

1. 第一阶段不实现自动发布、自动外发消息等高风险外部动作。
2. 第一阶段不要求完整替代 Notion、Obsidian 或企业级 DMS。
3. 图数据库是可选增强，不作为首个可运行版本的必需依赖。

## 4. 功能需求

### FR-01 知识资产管理

- 一个工作区可创建多个知识库，文档与笔记属于一个知识库。
- 笔记支持 Markdown、标签、来源与版本号。
- 文档保留原始文件元数据、提取文本、解析状态与索引版本。

### FR-02 可配置入库

- 入库任务使用指定的解析器、切块器、嵌入器与索引器。
- 各阶段状态可查询：`queued/running/succeeded/failed/cancelled`。
- 失败应保留安全的错误摘要和重试次数，支持幂等重试。

### FR-03 证据优先问答

- 回答必须带至少一个可访问的引用，无法支撑的结论不得伪造引用。
- 检索支持知识库、文档、标签、时间等过滤条件。
- 返回检索和重排元数据，供前端“检索调试”页面展示。

### FR-04 Agent 与审批

- Agent 只能通过注册工具访问系统能力。
- 所有创建、修改、删除等写操作先生成提议变更（proposal）。
- 提议变更含目标、差异、依据、风险等级和过期时间；批准后才执行。

### FR-05 扩展能力

- 解析器、切块器、嵌入模型、向量存储、重排器、LLM Provider、Agent Tool 必须可替换。
- 内置扩展通过配置启用；外部扩展可通过 Python entry point 或 MCP 接入。

### FR-06 企业级检索增强

- 召回至少支持向量、全文和可选 GraphRAG-lite，并保留通用召回兜底；定向标签/实体召回不得扩大工作区或知识库边界。
- 证据组装必须受模型 Token 预算约束，超限时优先保留高相关证据、条件限制、操作步骤、代码围栏和可校验来源。
- Rerank、Dynamic Top-K、业务标签权重和 Query Rewrite 均必须可关闭、可回退并纳入版本化评测，不得只凭演示结论启用。
- 回答中出现的外部链接必须来自证据或 approved domain，并经过可用性校验；失效来源必须显式标记。

### FR-07 知识质量与反馈闭环

- 文档支持来源可信度、生效/到期时间、受控标签、冲突状态和 `supersedes` 替代关系；网页来源支持按部署侧显式启用的低频批量复核。笔记支持来源、更新时间和受控标签。自动标签/知识草稿只能进入待审核状态。
- 用户可对回答提交 helpful/unhelpful 及原因；反馈应关联路由、检索、重排、截断和生成阶段摘要，而不保存敏感正文。
- 分诊结果可转为知识草稿、缺陷或回归评测用例；任何草稿入库必须经过用户或授权角色确认。

## 5. 非功能需求

- API 使用版本化 `/api/v1` 路径，错误码稳定且可机器解析。
- 生产环境不得记录密钥、原始 Authorization 值或完整敏感文档内容。
- 读写操作要有请求 ID；Agent、入库和审批操作要有审计 ID。
- 单元测试覆盖领域规则和异常映射；集成测试覆盖关键 API 契约。
- 默认使用 PostgreSQL + pgvector；本地开发允许 SQLite 运行基础领域能力。
- 证据组装、Agent 多步检索和外部 URL 校验必须有明确的 Token、步数、延迟、候选数和重定向上限。

## 6. 验收原则

每项功能需同时满足：正常路径、无权限/资源不存在、参数非法、可重试失败和审计记录。
任何 Agent 写入功能如果没有审批测试，即不算完成。
